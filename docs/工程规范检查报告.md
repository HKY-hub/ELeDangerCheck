## 四、问题清单

### 问题 1 · 双 git 仓库嵌套，远程与分支不一致（风险：高）

**现象**
- `d:\AGENT` 是一个独立仓库：远程 `https://gitee.com/three-gorges-university_11/maple.bb`，当前分支 `develop`
- `d:\AGENT\ELeDangerCheck` 又是一个独立仓库：远程 `https://github.com/HKY-hub/GameTextInjector.git`，当前分支 `DEVELOP`

**证据**
```
d:\AGENT>                 git remote -v  → gitee.com/three-gorges-university_11/maple.bb
d:\AGENT>                 git branch     → develop
d:\AGENT\ELeDangerCheck>  git remote -v  → github.com/HKY-hub/GameTextInjector.git
d:\AGENT\ELeDangerCheck>  git branch     → DEVELOP
```

**风险**：两个仓库相互嵌套，父仓库会把子仓库目录当作普通目录跟踪，极易造成「同一份代码被提交到两个远程」或「子仓库改动在父仓库丢失」。同时 `AGENT_ENVIRONMENT_RULES.md` 中写明「不再使用 Gitee（旧远程 maple.bb 已废弃）」「本仓库已切换至 GameTextInjector」——与实际根仓库状态**直接矛盾**，后续接手者会按错误信息操作。

**建议**：二选一——(a) 删除根仓库的 git 元数据，只保留 `ELeDangerCheck` 一个仓库；(b) 把 `ELeDangerCheck` 作为子模块（submodule）或普通目录纳入根仓库，并统一远程。同时修正 `AGENT_ENVIRONMENT_RULES.md` 中关于远程仓库的描述。

### 问题 8 · 治理文档含明文密钥（风险：高）

**现象**：`AGENT_ENVIRONMENT_RULES.md` 内含多组**明文凭据**，包括但不限于：大模型 API Key、云服务 SecretId/SecretKey、数据库 root 密码、GitHub 账号密码与 Personal Access Token。

**证据**：该文件第 56~66 行（Git 版本控制段）与第 133~155 行（第三方服务与 API 密钥段）以明文列出上述凭据。

> 本报告**不复制**任何密钥内容，仅标注其存在位置与类型。

**风险**
- 该文件虽已被 `.gitignore` 忽略（这点做对了），但一旦被误提交或转发，凭据即泄露
- GitHub PAT 具备 repo 全权限，泄露后果严重
- 项目自带规则文档明确要求「不要硬编码密钥，使用环境变量或配置文件注入」，此处自身即违反了该规则

**建议**
1. 将凭据从文档中剥离，改为环境变量或 `.env`（项目已有 `.env.example` 机制，可直接复用）
2. 文档中只保留「变量名 + 用途」说明，不写值
3. 已在文档中出现过的 PAT 与 API Key 建议**轮换**（视为已泄露）
4. 补 `.env.example` 的完整键位清单，降低接手成本

**现象**：根仓库分支为 `develop`（小写），子仓库分支为 `DEVELOP`（大写）。

**证据**
