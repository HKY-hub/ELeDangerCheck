## 出现的问题

1. **Docker Desktop 安装于 Windows 11 Home 版环境**：Home 版不支持 Hyper-V，需依赖 WSL 2 后端。经检查系统已预装 WSL，安装 Docker Desktop 后通过配置 WSL 2 后端成功运行。
2. **docker.elastic.co 镜像仓库无法访问（国内网络环境）**：由于网络限制无法拉取 Elasticsearch 和 Kibana 镜像。解决方案：在 docker-compose.yml 中将镜像源切换为 `docker.io/library/`，并配置国内镜像加速器（DaoCloud、DockerProxy、NJU），拉取成功。
3. **docker-credential-desktop 不在 PATH 环境变量中**：Git Bash 环境下 Docker 凭据助手无法找到，导致镜像拉取失败。通过配置 `~/.docker/config.json` 清空凭据存储解决。
4. **ES RAG 与规则引擎互斥问题**：原架构为 ES 命中则跳过规则引擎，导致燃气管道特定危险点（燃气泄漏爆炸、沟壁坍塌）被 ES 泛化结果覆盖。已改为并集合并+按名称去重，规则引擎保底 + ES 增强。
5. **Windows curl 中文编码问题**：Git Bash curl 发送含中文 JSON 时出现乱码，改用 Python requests 库完成 API 测试。

## 今天遇到的问题及解决过程描述

今天完成了项目里程碑式的进展——Phase 2 ES RAG 正式上线，危险点识别从单一的规则引擎升级为"规则引擎保底 + ES RAG 增强"的双引擎架构。

**ES RAG 部署过程**经历了多次波折。首先是 Docker Desktop 在 Windows 11 Home 版上的安装配置，系统没有 Hyper-V，需依赖 WSL 2 后端。安装成功后拉取 ES 镜像时发现 `docker.elastic.co` 被网络封锁，将镜像源切换为 Docker Hub 并配置国内镜像加速器后成功拉取。随后遇到 `docker-credential-desktop` 凭据助手问题，通过调整 Docker 配置解决。最终 ES 在 `localhost:9200` 成功运行，29 条事故案例通过 bulk API 导入索引。

**架构升级方面**，原有逻辑是 ES 命中则跳过规则引擎，导致新增的燃气管道特定危险点被泛化结果覆盖。改为并集合并策略——规则引擎和 ES RAG 分别独立运行，结果按危险点名称去重合并。这样既保留了规则引擎对安规条款的精准覆盖，又发挥了 ES 对案例库的检索增强能力。

**案例库扩充**方面，在原有的 24 条通用电力事故案例基础上，新增 5 条燃气管道/开挖场景的专项案例（燃气管道破裂爆炸、沟壁坍塌掩埋、交叉施工碰撞、燃气中毒、临近燃气管线触电），使案例总数达到 29 条，覆盖 13 种事故类型。

**规则引擎同步增强**，针对燃气管道开挖场景新增 4 组规则（燃气泄漏爆炸、地下管线破坏、沟壁坍塌、交叉作业碰撞伤害），并扩展了 TaskParserService 的 LLM prompt 示例和正则词典，确保"开挖""交叉施工""燃气"等关键词能被正确解析。

其他组员方面，黄开元完成了安全交底卡 Word 生成和电子签名模块，实现了从模板生成、签名采集到 PDF 导出的完整链路；田天乐完成了前端全页面的 UI 更新，统一了玻璃拟态暗色主题风格。

## 收获与感想综述

今天是项目进展最大的一天。Phase 2 ES RAG 的上线标志着危险点识别从"规则硬编码"升级到了"案例库智能检索"阶段，这与项目设计要求完全对齐。现在系统的工作流程是：用户输入作业任务 → LLM 解析关键要素 → 规则引擎匹配安规条款 + ES RAG 检索相似事故案例 → 合并去重 → 返回完整的危险点列表及控制措施。

Docker 容器化部署的经验对团队非常有价值，从安装配置到镜像加速再到网络问题排查，基本覆盖了国内环境下使用 Docker 的典型痛点。ES 的全文检索能力与规则引擎的精确匹配形成了良好的互补关系——前者覆盖案例库中的已知事故模式，后者确保安规条款的基本底线不遗漏。

安全交底卡模块和电子签名模块的完成为项目后续的"交底→确认→归档"完整业务流程奠定了基础。目前系统已经具备从任务录入到危险点识别到交底卡生成的核心闭环。
